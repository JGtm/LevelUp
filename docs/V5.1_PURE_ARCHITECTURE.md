# Architecture Pure v5.1 — Manifeste LevelUp

> **Version** : v5.1  
> **Date** : 2026-02-16  
> **Statut** : 🎯 Planifié (en cours d'exécution)  
> **Philosophie** : Zero Tolerance — Pas de fallback, pas de backward compatibility

---

## 🎯 Vision

LevelUp v5.1 incarne une architecture **pure, moderne et sans compromis** :

- **100% DuckDB** — Aucune trace de SQLite en runtime
- **100% Polars** — Aucune dépendance Pandas dans le code métier
- **Zéro legacy** — Aucun fallback vers les architectures obsolètes
- **Zéro dette technique** — Code propre, testable, maintenable

**Principe directeur** : *Choisir la simplicité et la rigueur plutôt que la rétrocompatibilité.*

---

## 🏗️ Stack Technique Pure

### Fondations

| Composant | Technologie | Raison |
|-----------|------------|--------|
| **Base de données** | DuckDB 1.4+ | OLAP performant, SQL analytique, zero-copy Arrow |
| **DataFrames** | Polars 1.38+ | Lazy evaluation, expressions optimisées, Rust backend |
| **API Halo** | SPNKr | Client Python moderne pour Halo Infinite API |
| **UI** | Streamlit 1.40+ | Prototypage rapide, interactivité |
| **Visualisation** | Plotly 5.24+ | Graphiques interactifs, thème personnalisable |
| **Validation** | Pydantic v2 | Type safety, validation runtime |

### Technologies PROSCRITES (v5.1+)

| Technologie | Statut | Raison |
|-------------|--------|--------|
| **SQLite** | ❌ INTERDIT en runtime | Remplacé par DuckDB (meilleure performance OLAP) |
| **Pandas** | ❌ INTERDIT en métier | Remplacé par Polars (lazy eval, expressions optimisées) |
| **JSON files** | ⚠️ DÉCONSEILLÉ | Préférer DuckDB (sauf config simple) |
| **CSV** | ⚠️ LIMITÉ | Autorisé pour export uniquement (pas de stockage primaire) |

**Exceptions tolérées** :
- Pandas **uniquement** à la frontière Plotly/Streamlit (modules `_compat.py`, `_arrow_bridge.py`)
- SQLite **uniquement** dans scripts de migration (dossier `scripts/migration/`)

## 📐 Principes Architecturaux

### 1. Single Source of Truth

**Données partagées** : `data/warehouse/shared_matches.duckdb`  
**Données personnelles** : `data/players/{gamertag}/stats.duckdb`  
**Référentiels** : `data/warehouse/metadata.duckdb`

**Règle** : Une donnée, un emplacement. Aucune duplication.

### 2. Immutabilité des Données de Match

Les données de match dans `shared_matches.duckdb` sont **immuables** :
- Pas de UPDATE
- Pas de DELETE
- INSERT uniquement lors de la synchronisation

**Bénéfices** :
- Auditabilité complète
- Simplification de la concurrence (READ_ONLY)
- Intégrité garantie

### 3. Lazy Evaluation Partout

**Polars** : Utiliser `.lazy()` autant que possible

```python
# ✅ BON — Lazy evaluation
df = pl.scan_parquet("data.parquet").filter(
    pl.col("kills") > 10
).group_by("player").agg([
    pl.col("kills").sum()
]).collect()

# ❌ MAUVAIS — Eager evaluation
df = pl.read_parquet("data.parquet")
df = df.filter(pl.col("kills") > 10)
df = df.group_by("player").agg([pl.col("kills").sum()])
```

**DuckDB** : Laisser le query planner optimiser

```python
# ✅ BON — Une seule requête optimisée
result = conn.execute("""
    SELECT player, SUM(kills) AS total_kills
    FROM match_stats
    WHERE kills > 10
    GROUP BY player
""").pl()

# ❌ MAUVAIS — Plusieurs requêtes + filtrage Python
all_data = conn.execute("SELECT * FROM match_stats").pl()
filtered = all_data.filter(pl.col("kills") > 10)
```

### 4. Type Safety Stricte

**Pydantic v2** pour toute validation de données :

```python
from pydantic import BaseModel, Field

class MatchSummary(BaseModel):
    match_id: str = Field(..., min_length=36, max_length=36)
    kills: int = Field(ge=0)
    deaths: int = Field(ge=0)
    
    @property
    def kd_ratio(self) -> float:
        return self.kills / self.deaths if self.deaths > 0 else float(self.kills)
```

**Type hints obligatoires** sur toutes les fonctions publiques :

```python
# ✅ BON
def compute_kd(kills: int, deaths: int) -> float:
    """Calcule le ratio K/D."""
    ...

# ❌ MAUVAIS
def compute_kd(kills, deaths):
    ...
```

### 5. Séparation des Préoccupations

```
src/
├── data/           # Couche accès données (repositories, sync)
├── analysis/       # Logique métier (calculs, agrégations)
├── ui/             # Interface utilisateur (pages, composants)
├── visualization/  # Graphiques Plotly
└── utils/          # Utilitaires purs (paths, xuid, etc.)
```

**Règle** : Une couche ne doit jamais importer d'une couche supérieure.

**Autorisé** :
- `ui/` → `analysis/` → `data/`
- `visualization/` → `data/`

**Interdit** :
- `data/` → `ui/`
- `analysis/` → `ui/`

## 🔌 Repository Pattern

### Principe

**Un seul repository** : `DuckDBRepository`

```python
from src.data.repositories import DuckDBRepository

# Initialisation (auto-ATTACH shared + meta)
repo = DuckDBRepository(db_path="data/players/MonGT/stats.duckdb", xuid="...")

# Chargement matches (JOIN automatique shared + enrichment)
matches = repo.load_matches(limit=100)
# → pl.DataFrame avec colonnes de shared.match_participants + player_match_enrichment

# Accès sous-requête unifiée
df = repo._get_match_source()  # Alias SQL "match_stats"
```

### Interdictions

❌ **NE JAMAIS** :
- Utiliser `duckdb.connect()` directement dans les pages UI
- Ouvrir plusieurs connexions au même fichier
- Faire des `SELECT *` sans filtrage
- Utiliser `sqlite3.connect()` (proscrit)

✅ **TOUJOURS** :
- Passer par `DuckDBRepository`
- Utiliser les méthodes du repository (`load_matches`, `load_roster`, etc.)
- Filtrer au niveau SQL (pas Python)

## 🔒 Sécurité

### 1. SQL Injection Prevention

**Règle absolue** : Paramètres SQL avec placeholders `?`

```python
# ✅ BON — Paramétré
conn.execute("SELECT * FROM matches WHERE match_id = ?", [match_id])

# ❌ MAUVAIS — Injection SQL
conn.execute(f"SELECT * FROM matches WHERE match_id = '{match_id}'")
```

**Exceptions tolérées** : Noms de colonnes dynamiques APRÈS whitelist

```python
VALID_METRICS = {"kills", "deaths", "assists"}

def query_metric(metric: str):
    if metric not in VALID_METRICS:
        raise ValueError(f"Invalid metric: {metric}")
    return conn.execute(f"SELECT {metric} FROM matches").pl()
```

### 2. Secrets Management

**Interdictions** :
- ❌ Hardcoder des tokens dans le code
- ❌ Committer `.env` avec secrets
- ❌ Logs contenant des tokens

**Bonnes pratiques** :
- ✅ Variables d'environnement (`SPNKR_SPARTAN_TOKEN`)
- ✅ `.env.local` (gitignored)
- ✅ Secrets scrubbing dans logs

### 3. Input Validation

**Toute entrée utilisateur** doit être validée avec Pydantic :

```python
class FilterParams(BaseModel):
    playlist_id: str | None = None
    map_id: str | None = None
    min_kills: int = Field(ge=0, le=200)
    
# Usage
params = FilterParams(**user_input)  # Validation automatique
```

## 📊 Performance

### Optimisations DuckDB

1. **Memory limit** : `SET memory_limit = '4GB'`
2. **Threads** : `SET threads = 4` (ajuster selon CPU)
3. **Object cache** : `SET enable_object_cache = true`
4. **Indexes** : Sur colonnes fréquemment filtrées

```sql
CREATE INDEX idx_match_participants_xuid ON match_participants(xuid);
CREATE INDEX idx_medals_match_id ON medals_earned(match_id);
```

### Optimisations Polars

1. **Lazy frames** : Toujours préférer `.lazy()` → `.collect()`
2. **Predicate pushdown** : Filtrer tôt dans la chaîne
3. **Projection pushdown** : Ne sélectionner que les colonnes nécessaires

```python
# ✅ BON
df = pl.scan_parquet("data.parquet").select([
    "match_id", "kills", "deaths"
]).filter(
    pl.col("kills") > 10
).collect()

# ❌ MAUVAIS
df = pl.read_parquet("data.parquet")  # Lit tout
df = df.filter(pl.col("kills") > 10)
df = df.select(["match_id", "kills", "deaths"])
```

| Calcul citations 1000 matchs | **< 1s** |

## 🚫 Anti-Patterns à Éviter

### 1. Le God Object Repository

```python
# ❌ MAUVAIS — Repository qui fait tout
class SuperRepository:
    def load_data(self): ...
    def compute_stats(self): ...
    def render_chart(self): ...
    def send_email(self): ...
```

**Solution** : Séparer responsabilités (repository = données, service = logique, UI = rendu)

### 2. Le DataFrame Eager à Tous les Étages

```python
# ❌ MAUVAIS
def process(df: pl.DataFrame) -> pl.DataFrame:
    df = df.filter(...)  # Eager
    df = df.with_columns(...)  # Eager
    df = df.group_by(...)  # Eager
    return df
```

**Solution** : Lazy frames

```python
# ✅ BON
def process(df: pl.LazyFrame) -> pl.LazyFrame:
    return df.filter(...).with_columns(...).group_by(...)

# Usage
result = process(df.lazy()).collect()
```

### 3. Le SELECT * dans une Boucle

```python
# ❌ MAUVAIS
for match_id in match_ids:
    conn.execute("SELECT * FROM matches WHERE match_id = ?", [match_id])
```

**Solution** : Requête batch

```python
# ✅ BON
placeholders = ", ".join("?" * len(match_ids))
conn.execute(f"SELECT * FROM matches WHERE match_id IN ({placeholders})", match_ids)
```

### 4. La Conversion Pandas Partout

```python
# ❌ MAUVAIS
def compute(df: pl.DataFrame) -> pl.DataFrame:
    pdf = df.to_pandas()  # Conversion
    # ... logique Pandas ...
    return pl.from_pandas(pdf)  # Re-conversion
```

**Solution** : Rester en Polars

```python
# ✅ BON
def compute(df: pl.DataFrame) -> pl.DataFrame:
    return df.with_columns([
        pl.col("kills").alias("total_kills")
    ])
```

### Imports

**Ordre** (isort) :
1. Standard library
2. Third-party (polars, duckdb, streamlit, ...)
3. Local (`src.data`, `src.analysis`, ...)

**Aliases standards** :
```python

```

### Naming

| Type | Convention | Exemple |
|------|-----------|---------|
| Variables | `snake_case` | `match_id`, `total_kills` |
| Fonctions | `snake_case` | `compute_kd_ratio()` |
| Classes | `PascalCase` | `DuckDBRepository` |
| Constantes | `UPPER_SNAKE_CASE` | `MAX_MATCHES` |
| Privées | `_leading_underscore` | `_internal_method()` |

### Docstrings

**Format** : Google style, en français

```python
def compute_kd_ratio(kills: int, deaths: int) -> float:
    """Calcule le ratio kills/deaths.
    
    Args:
        kills: Nombre de kills
        deaths: Nombre de morts
        
    Returns:
        Ratio K/D. Si deaths = 0, retourne kills en float.
        
    Examples:
        >>> compute_kd_ratio(10, 5)
        2.0
        >>> compute_kd_ratio(10, 0)
        10.0
    """
    if deaths == 0:
        return float(kills)
    return kills / deaths
```

## 🌟 Success Stories v5.1

### Avant v5.1 (Legacy)

```python
# ❌ Code legacy avec Pandas + SQLite fallback
import pandas as pd
import sqlite3

def load_matches(db_path: str):
    # Fallback SQLite → DuckDB
    if db_path.endswith(".db"):
        conn = sqlite3.connect(db_path)
    else:
        conn = duckdb.connect(db_path)
    
    # Pandas
    df = pd.read_sql("SELECT * FROM matches", conn)
    return df.fillna(0)
```

**Problèmes** :
- Deux backends (SQLite + DuckDB)
- Pandas (lent, eager)
- SELECT * (inefficace)

### Après v5.1 (Pure)

```python
# ✅ Code v5.1 avec Polars + DuckDB pur
import polars as pl
from src.data.repositories import DuckDBRepository

def load_matches(gamertag: str, xuid: str, limit: int = 100) -> pl.DataFrame:
    """Charge les matchs via repository unifié."""
    repo = DuckDBRepository(
        db_path=f"data/players/{gamertag}/stats.duckdb",
        xuid=xuid
    )
    return repo.load_matches(limit=limit)
```

**Bénéfices** :
- Un seul backend (DuckDB)
- Polars (lazy, optimisé)
- Repository pattern (testable)
- Type hints (safety)
