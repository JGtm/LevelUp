Campagne d'audits « périmètre × axe » sur la fenêtre `v8.1.3..HEAD` (HEAD = `71cf7db427`, tête de
`release/v8.3.0`). Question posée par le user : sur-ingénierie, divagations, qualité du code, pertinence,
séquençage des opérations, séparation des couches. L'audit ne corrige rien.

## Constats retenus

### [P1] Image « plan » des cartes : l'ADR 0048 D-3 dit « jamais une seconde image »
- Où : `docs/adr/0048*.md:39` ; `data/titles/halo_infinite/reference/map_backgrounds/*.plan.webp` (111 fichiers,
  7,27 Mo) ; `cmd/mapfond-build/plan_fond.go` ; `handlers/background_variante.go` ;
  `service/replay_map_background_plan.go` ; `lib/replay/mapBackgroundVariant.ts:19` (défaut « plan »).
- Règle : ADR 0048 D-3 ; anti-pattern « doc inversée ».
- Conséquence : le plan existe en vecteur dans chaque sidecar (11 Mo) et en image ; l'image est le défaut, le
  vecteur n'est dessiné que sur le fond « rendu ». L'ADR est faux sur ce point depuis le jour de sa rédaction.
- Reproduction : `ls data/titles/halo_infinite/reference/map_backgrounds/*.plan.webp | wc -l ; grep -n "second image" docs/adr/0048*.md`
- Vérification : tient. La vue plan en image a été validée à l'écran par le user (13/11) : c'est l'ADR qui est à
  amender, pas l'image à retirer.
- Décision : ESCALADE user (ADR).

### [P1] Ligne de vue des réapparitions : mesurée, écartée, restée dans l'arbre
- Où : `analysis/tactical/ligne_de_vue.go` (142 l) ; `reapparition.go:55,173-186` ;
  `reapparition_ajustement.go:223-227` ; `cmd/levelup/cmd_spawn_model*.go` (option `--ligne-de-vue`, section M-2) ;
  production : `previsions_reapparition.go:248` passe `nil`.
