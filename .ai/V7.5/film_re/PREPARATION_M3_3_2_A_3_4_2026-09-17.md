func registryHasher() *registryFNV { return &registryFNV{h: fnv.New64a()} }

// addEntry ajoute `niveau | nom` d'une entree nommee. `off` est l'octet de l'ENTREE.
func (f *registryFNV) addEntry(data []byte, off int, name string) {
	lv := off + registryEntryLevelOffset
	if lv+4 > len(data) {
		return
	}
	_, _ = f.h.Write(data[lv : lv+4]) // u32 niveau LE, octets du fichier
	_, _ = f.h.Write([]byte(name))
	f.slots++
}

func (f *registryFNV) sum() uint64 { return f.h.Sum64() }

// RegistryFingerprint rend l'empreinte du registre lu. Zero pour un registre nil.
func RegistryFingerprint(reg *Registry) uint64 {
	if reg == nil {
		return 0
	}

### 1.4 La forme de l'entree de profil

Le catalogue existe depuis 3.1.2 et sa grammaire est fermee. `filmprofile/catalogue.go:223-237` :

```go
type Entree struct {
	Cle    string     `json:"key"`         // `format=27`, `build=HI_1_13_0`, `majeure>=41`, `toutes`
	Champ  string     `json:"field"`
	Valeur string     `json:"value"`       // ecrite pour etre lue par un humain
	Source Provenance `json:"provenance"`  // relue | mesuree | presumee
	Preuve string     `json:"proof"`
	Date   string     `json:"date"`

```

Les quatre sortes de cle (`catalogue.go`, `SorteDeCle`) : `format`, `build`, `majeure`, `toutes` ;
comparateurs `=`, `<=`, `>=`. Une entree 3.2.1 s'ecrit donc sans etendre la grammaire :

```json
{
  "key": "build=HI_1_11_0",
  "field": "Registry.Empreinte",
  "value": "0x8879e2b6746ba047 (49 blocs, 1031 slots nommes) — statut: presumee",
  "provenance": "mesuree",
  "proof": "corpus gate du 2026-09-16, temoin e5adf7b2 : WARN `empreinte du registre ECS du film INCONNUE`, empreinte 9834140534605324359, blocs 49, slots_non_vides 1031 (work_m1_cloture/logs/general.log)",
  "date": "2026-09-17"
}
```

**Le statut connue / presumee / inconnue demande par l'item 3.2.1 n'est PAS la `provenance`.** Ce
sont deux axes orthogonaux, et les confondre est le piege de ce lot :

- `provenance` dit d'ou vient la LIGNE (relue chez l'ecrivain / mesuree sur temoin / presumee) ;
- le statut dit ce que le decodeur SAIT de l'empreinte LUE DANS LE FILM QU'IL DECODE : `connue`
  (elle est au catalogue), `presumee` (une ligne du catalogue la donne avec `provenance: presumee`),
  `inconnue` (aucune ligne). C'est une **classification a l'execution**, pas une donnee du fichier.

Consequence de conception a trancher (§6, Q3) : soit une valeur de champ composite comme ci-dessus
(le catalogue ne porte que des `string`), soit un champ par grandeur (`Registry.Empreinte`,
`Registry.Blocs`, `Registry.SlotsNommes`) — trois lignes par build, plus verbeuses mais
comparables machine a machine sans analyse de chaine. La seconde forme est la seule qui permette
au test de conformite de mordre sur une valeur, pas sur une phrase.
