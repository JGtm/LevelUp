## Pourquoi ce journal existe

M1 (`.ai/DECOUVERTES_TACTIQUE_2026-09-07.md`) avait posé le lien « voir dans le rejeu »
depuis une cellule Tactique, mais laissé une réserve : pour quatre questions sur six

ouvrait donc une APPROXIMATION pour ces quatre questions.

## Le champ

`coverage.bridge.deathOffsetMs` : `*int64`, additif, `omitempty`. C'est le calage
`OwnerReport.DeathOffsetMS` lui-même (déjà calculé à la cuisson depuis le lot v48 — celui-ci
publiait sa MARGE, `deathOffsetMatched`/`deathOffsetRunnerUp`, jamais la valeur). Pointeur,
même piège `omitempty` que `OriginMs`/`T0FilmMs` : absent (nil) veut dire, et seulement, que
le pont d'identité n'a apparié AUCUNE mort (`OwnerReport.DeathOffsetMatches == 0`) — un
calage mesuré à zéro (horloges déjà alignées) est une VALEUR, pas une absence, et doit rester
publiable. Garde-fou : `TestDeathOffsetMsAbsentWhenBridgeUnmatched`
(`internal/analysis/replay/coverage_test.go`) verrouille les deux bornes (0 apparié -> nil ;
0 exact mais apparié -> `*0`).

## Pourquoi le bump, alors que le champ est optionnel

La règle de tête de `document.go` dit qu'un champ optionnel de plus n'incrémente pas la
version. Ce bump est une EXCEPTION assumée, pour la même raison que v2→v3 et v3→v4 (chronique
dans `document.go`/`structure_test.go`) : c'est la clé de REPRISE du backfill.
`backfill-replay` saute un artefact déjà à la version courante — sans le bump, un artefact
< 49 répondrait « calage inconnu » indéfiniment, faute de recuisson déclenchée. Le web sait
déjà distinguer « connu » de « absent » sur le seul pointeur (il n'a pas besoin de lire la
version pour ça).
