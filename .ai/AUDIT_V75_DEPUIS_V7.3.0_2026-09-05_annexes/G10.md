## Constats (du plus grave au moins grave)

### [P0] Le runtime ÉCRIT un catalogue versionné, et chaque déploiement l'ÉCRASE — perte silencieuse en prod, données non relues en local

- Où :
  - écrivain runtime : `apps/go-api/internal/sync/replayartifacts/mvar_rattrapage.go:175-236` (`ajouterCarteAuCatalogue` → `mapcatalog.AddEntry`), appelé par `apps/go-api/internal/sync/replayartifacts/artifacts.go:320`, câblé en prod par `apps/go-api/internal/sync/convergence.go:622` (`s.client.(replayartifacts.MvarFetcher)`) ;
  - cible : `apps/go-api/internal/domain/title/registry.go:798` → `data/titles/{slug}/reference/map_weapon_pads.json`, fichier **suivi par git** ;
  - écriture : `apps/go-api/internal/mapcatalog/store.go:104` (`AddEntry`) / `:121` (`WriteAtomic`) ;
  - effacement : `scripts/deploy.sh:33` `git reset --hard origin/main` (le `git clean --exclude=data/` de la ligne 34 ne protège que les fichiers NON suivis) ;
  - montage : `docker-compose.yml:48` `- ./data:/app/data` en lecture/écriture, `PathResolver.TitleDataDir` = `<repoRoot>/data/titles/<slug>` (`registry.go:488`).
- Règle enfreinte : gravité de la campagne — « **P0 donnée versionnée corrompue/réécrite par le runtime** ». Le code le sait : `mvar_rattrapage.go:97` écrit « le catalogue est **VERSIONNE** » et écrit dedans quand même.
- Conséquence, deux fois concrète :
  1. **En prod** : `/opt/levelup` est un clone git ; chaque `git reset --hard origin/main` du déploiement (= chaque push sur `main`) rend le catalogue à sa version commitée et **jette les cartes que la synchro y avait ajoutées**. Le rattrapage n'itère que sur le lot de films en cours (`rattraperCartesAbsentes(ctx, d, work, …)`), donc une carte dont tous les films sont déjà récupérés **n'est jamais réajoutée** : ses artefacts de rejeu retombent définitivement en `coverage.pickups.spawnPointsState == "map_absent"` (origine de ramassage `spawner` impossible, cf. l'en-tête du fichier lui-même).
  2. **En local, c'est déjà arrivé** : le commit `5426e256b` (2026-09-04), intitulé « journal(wip): deux entrees d une session parallele » et dont le message dit « Commitees **TELLES QUELLES, sans relecture ni modification** », ajoute **+332 lignes** à `map_weapon_pads.json` — l'entrée complète de la carte « Detachment » (`d39600e2-…`, 4 511 objets, ses socles). De la donnée de référence est entrée au dépôt sans revue, dans un commit dont le titre ne la mentionne pas.
- Reproduction : `git show --numstat 5426e256b -- data/titles/halo_infinite/reference/map_weapon_pads.json && git ls-files --error-unmatch data/titles/halo_infinite/reference/map_weapon_pads.json && sed -n '33p' scripts/deploy.sh`
- Traitement proposé (v2) : sortir le rattrapage du fichier versionné — écrire les cartes découvertes à l'exécution dans un **overlay non suivi** (`data/titles/{slug}/reference/generated/map_weapon_pads_overlay.json`, ignoré par git), que `LoadMapWeaponPads` fusionne au-dessus du catalogue versionné ; la promotion d'une entrée vers le catalogue reste un acte d'outil (`mapopads-build`) et de revue.

## Vue d'ensemble pour une v2

1. **La frontière binaire est bonne, il faut la nommer.** Aucun paquet servi n'importe `himap/himodule/ooz/hinavmesh/mapdecoupe` : le serveur n'est lié ni à Oodle (GPLv3) ni au jeu installé. Poser un test `archlint` qui **interdit** cet import depuis `api/ service/ platform/ analysis/ sync/ persist/ port/ replaybuild/` fige un acquis qui n'est aujourd'hui garanti par rien.
2. **Le contrat qui sépare l'outil du runtime, ce sont les catalogues — et il fuit à un seul endroit.** `map_weapon_pads.json` est écrit à l'exécution (P0). Le contrat se rétablit par un **overlay non versionné** fusionné en lecture : la chaîne de fabrication reste seule à écrire du versionné, le runtime n'écrit que du généré.
3. **Un seul paquet pour les catalogues.** Aujourd'hui : lecture dans `analysis/replay` (7 loaders + cache global), écriture dans `mapcatalog`, choix de variante dans `mapcatalog`, client UGC dans `mapcatalog`, résolution d'identité éclatée en 9 endroits sur 4 formes de clé. Cible : `internal/platform/mapref/` derrière un `port.MapReferenceStore` (loaders, index, overlay, écriture atomique via `platform/atomicfile`) ; `analysis/replay` ne garde que les types et les fonctions pures ; `mapcatalog` disparaît, sa partie UGC va au client Halo.
4. **Une seule identité de carte.** Un `mapref.Identity{MapID, Module, Names}` construit une fois par `ReplayMapRepo`, essayé par un unique résolveur ; `NormalizeMapName` et `NormalizeMapIdentity` deviennent deux stratégies d'un même point d'entrée, et les trois listes de suffixes de variante n'en font plus qu'une, avec le garde-rail grep qu'exige R6.
5. **À supprimer** : `internal/himap/heightfield.go` + son test (175 L), `himap.NewVolume`, `himap.NoeudParNom`, `himap.Instance.MeshKey` ; dé-exporter les 62 symboles sans appelant externe. **À déplacer en donnée** : `himap.CartesForge` (89 cartes, 681 L de Go). **À déplacer sous `games/halo_infinite/maps/`** : les cinq paquets Halo-only.
6. **Un ratchet, pas un test local.** `corpus_tag_test.go` garde un seul répertoire ; deux tests hors `himap` ouvrent déjà l'installation. Le déplacer en `internal/archlint/` avec balayage du module entier, et lui ajouter la règle de taille de fichier (R5), qui n'a aujourd'hui aucun garde-rail.
